During this session you may clarify requirements with the user.
Before exiting:
1. Save the (possibly refined) requirements summary to %q (overwrite if
   it exists). Write requirements.md as a PM/QA-style spec: start with a
   concise one-line summary, not `# Requirements`; then include user
   story, behavioral acceptance criteria, and out-of-scope notes when
   useful.
   Do not include file paths, function signatures, internal architecture,
   or implementation steps; those belong in plan.md.
2. Save the plan to %q (overwrite if it exists).
   plan.md is the technical companion to requirements.md. Include
   numbered implementation steps, likely file boundaries, methods,
   functions, prompt fragments, or tests to modify, add, or delete when
   known, refactors or architecture notes, verification commands, and
   acceptance criteria.

Then exit.
